## Visual Pull-Request Blast-Radius Reports (`arc diff`)

When reviewing a pull request, seeing a list of 30 changed files rarely tells you how the system's architecture changed — or which upstream callers could be affected.

Running `arc diff` compares your branch against a baseline snapshot and generates a **GitHub / GitLab Pull Request Markdown report** complete with an interactive Mermaid diagram:
- Lists **Added**, **Modified**, and **Removed** components.
- Computes the **Upstream Blast Radius (`⚡ BLAST RADIUS`)** — identifying every upstream controller, client, or service that transitively depends on a modified or removed component.
- Flags any newly introduced **Circular Dependencies**, **Boundary Violations**, or **Broken REST Contracts**.

## Adding ArcDrift to GitHub Actions

Add the following workflow (`.github/workflows/architecture.yml`) to check every pull request and generate a blast-radius report:

```yaml
name: Architecture Compliance
on:
  pull_request:
    branches: [main]

jobs:
  arcdrift-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: 21

      - name: Verify Boundary Rules, Cycles & REST Contracts
        run: arc check . --spec architecture.arc.mmd

      - name: Generate Pull Request Blast-Radius Report
        if: always()
        run: arc diff architecture.arc.mmd . --format markdown --output arcdrift-pr-report.md
```

## Generating JUnit 5 `ArchUnit` Tests

If your team already runs JUnit 5 tests on every build, you can export your `architecture.arc.mmd` rules directly into a standalone Kotlin **`ArchUnit`** test class:

```bash
arc check . \
  --spec architecture.arc.mmd \
  --generate-archunit src/test/kotlin/com/acme/ArchitectureComplianceTest.kt
```

The generated test class enforces all `FORBIDDEN`, `ALLOWED_ONLY`, and `MUST_DEPEND_VIA_INTERFACE` rules from `architecture.arc.mmd` as well as a package cycle check (`slices().should().beFreeOfCycles()`) as part of your standard `./gradlew test` suite.

## Exporting SARIF (`2.1.0`) & SonarQube External Issues

If your organization already uses **GitHub Code Scanning** or **SonarQube** as its central quality gate, `arc check` can export cross-language contract violations, boundary rule breaches, and circular dependencies directly into their native formats:

```bash
# Export SARIF v2.1.0 for GitHub Code Scanning / GitLab SAST
arc check . --format sarif --output build/reports/arcdrift.sarif

# Export SonarQube Generic Issue Import JSON for sonar.externalIssuesReportPaths
arc check . --format sonar --output build/reports/arcdrift-sonar.json
```
